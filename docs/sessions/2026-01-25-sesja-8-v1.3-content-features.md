## Kluczowe decyzje techniczne

1. **Cover Upload - base64 w PDF, binary w EPUB**
   - PDF: inline data URI (no external dependencies)
   - EPUB: binary EpubImage (proper ebook format)
   - Result: covers work reliably in both formats ✅

2. **Images - deduplication w EPUB**
   - Global image_map prevents downloading same URL twice
   - Performance optimization dla books z powtarzającymi się obrazkami
   - PDF: per-chapter (could optimize later)

3. **Images - base64 w PDF zamiast URLs**
   - WeasyPrint może fetchować z URL, ale unreliable (network)
   - Base64 inline: self-contained PDF, działa offline
   - Trade-off: większy file size, ale pewność działania

4. **Chapter Spacing - h1 margin-bottom**
   - Spacing pod nagłówkiem rozdziału (h1), nie między paragrafami
   - Kontroluje odstęp między titleem a contentem
   - CSS variable z fallback (var(--chapter-spacing, 2em))

5. **Supabase Storage - assets bucket PUBLIC**
   - Początkowo 404 error - bucket nie był public
   - Fix: UPDATE storage.buckets SET public = true WHERE id = 'assets'
   - RLS policy: public SELECT, authenticated INSERT/DELETE

6. **TipTap Image Extension - inline mode**
   - inline: true - images flow with text
   - allowBase64: false - używamy tylko URLs (Supabase Storage)
   - Auto-save existing debounce handles image URLs

## Problemy i rozwiązania

### Problem 1: Bucket assets zwraca 404
**Symptom:** URL w DB jest OK, ale otwieranie w przeglądarce → {"statusCode":"404","error":"Bucket not found"}
**Root cause:** Bucket istnieje ale nie jest publiczny
**Fix:** Supabase UI → Storage → assets → ⚙️ Edit bucket → Public bucket ✅
**Alternative:** SQL `UPDATE storage.buckets SET public = true WHERE id = 'assets'`

### Problem 2: Chapter z NULL processed_html nie generuje się
**Symptom:** 2 chapters w bazie, tylko 1 w PDF
**Root cause:** Drugi chapter nie miał treści (processed_html = NULL)
**Fix:** Dodanie dowolnego tekstu w edytorze → auto-save → Generate ✅
**Backend:** Filtrowanie chapters bez treści (już było w kodzie)

### Problem 3: Chapter spacing nie widać w UI
**Symptom:** Slider działa, ale nic się nie zmienia
**Root cause:** Spacing kontroluje EPUB/PDF, nie edytor UI
**Clarification:** Spacing = odstęp POD h1 w wygenerowanym ebooku, nie w edytorze
**Test:** Generate PDF z 0.5em vs 4em → widoczna różnica ✅
